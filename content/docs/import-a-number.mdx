title: Import a number you own

Use **Numbers → Import a number** for a number you already own at DIDWW, DIDLogic or
Telnyx. You keep the number and its carrier account. This does not purchase
a number, transfer ownership, or port it to Skysay.

<Walkthrough id="import-a-number" tab="didww" />

## DIDWW: connect with one API key

You need a DIDWW account, and DIDWW must already have approved your number for
the calls you want to make. DIDWW keeps control of its own verification,
outbound calling permission, balance and restrictions. Connecting the number
to Skysay does not get around any of them.

To start, open **Numbers** in Skysay and choose **Import a number**.

<Steps>

<Step>

### Create a DIDWW API key

Sign in to [DIDWW](https://my.didww.com/) and open **APIs → DIDWW API 3 →
Create new API Key**. Name the key Skysay, choose **Create**, and copy the
key. DIDWW's own [API-key guide](https://doc.didww.com/api3/configuration.html)
walks through these screens.

</Step>

<Step>

### Paste the key and list your numbers

In the **Import from your carrier** window, choose **DIDWW** as the carrier,
paste your production API key and choose **List my numbers**. Skysay only
reads the numbers on your DIDWW account here. Nothing changes at DIDWW yet.

  src="/docs-assets/images/docs/import-a-number/didww-api-key.webp"

/>

</Step>

<Step>

### Choose a number and what it should do

Choose **Select** next to the number you want to connect. To find one number,
type the complete number into the search box. On a large account, use **Next
page**.

<img
  src="/docs-assets/images/docs/import-a-number/choose-a-number.webp"
  alt="A list of three example numbers on the DIDWW account, each marked Billed by your carrier and Incoming available, with a Select button"
  width="1152"

Then decide what the number should do:

- **AI agent for incoming calls**: pick one of your published AI agents to
  answer calls to this number. If you are not ready, choose **Set up incoming
  later**. Calls then keep going where they go today.
- **Connect outgoing calls**: tick this if your AI agents should also call out
  from this number.

This import connects calls only, not SMS, even if DIDWW offers SMS on the
number.

<Step>

### Review and confirm

Choose **Review setup**. Skysay shows the number, where its incoming calls go
today, what will change, and who bills what. Tick the confirmation box and
choose **Connect this number**, or **Save number** if you connected neither
direction.

Skysay then creates dedicated SIP trunks in your DIDWW account and sets up
their credentials, destination and caller ID for you. You never enter a SIP
username, password or host.

### Check the result

Skysay reports incoming and outgoing calls separately. **Incoming setup
complete** and **Outgoing configured** mean Skysay checked the saved setup at
DIDWW at that moment. They do not mean a call has already gone through, and
Skysay does not keep checking your DIDWW permissions afterwards.

### Details

**Incoming route.** Connecting incoming calls replaces the number's existing
DIDWW incoming route, including a trunk group if one is assigned. Other
numbers and unrelated trunks are left alone. Do not edit the same route at
DIDWW while you connect the number. Skysay checks the route again just before
it switches and stops if it sees a change. DIDWW cannot make that switch in
one step that applies only if nothing changed, so Skysay cannot guarantee
safety if someone edits the route at the same moment.

**API key.** The key gives API access to your whole DIDWW account; it is not
read-only. Skysay uses it only during each setup request and does not keep it.
Skysay stores only the SIP credentials this connection needs, encrypted. Those
credentials can place calls through your DIDWW account. To refresh, retry or
add a direction later, enter the API key again.

**IP-restricted keys.** If your DIDWW API key only works from approved IP
addresses, contact support before connecting it. This import does not yet
come from fixed Skysay API addresses that you could approve. Keep your
existing restrictions. The Skysay voice-server address and your own
computer's address cannot stand in for the Skysay API's address.

## Billing and availability

DIDWW bills your number rental and carrier traffic directly. Skysay charges
its applicable AI and platform usage from your workspace balance; it does not
add managed-number rental or another carrier traffic charge. Check
**Billing** for the platform rates and usage. Calls still obey Skysay's trust,
destination, caller-ID, balance and concurrency controls.

Incoming and outgoing are connected separately. A number saved for later can
remain pending, and a number with one configured direction cannot use an
unconnected direction. This import does not connect SMS, even if DIDWW offers
SMS on the number. The dedicated outgoing trunk permits only this caller ID
and one concurrent call; DIDWW's existing account controls continue to apply.

## Retry, change or disconnect

Open the imported number and choose **Re-enter API key** to connect a deferred
direction or review a setup change. The key must still access the same DID and
the integration's recorded trunks. Skysay reads the current route and asks for
fresh confirmation. Changing the local AI-agent rule alone cannot connect a
deferred DIDWW route.

If setup is interrupted, check the number before retrying. Skysay reconciles
recorded resources rather than blindly creating duplicates. An ambiguous
resource requires support. A failure in an added direction leaves a previously
configured direction available when its configuration is unaffected.

**Disconnect from Skysay** revokes this connection's runtime access. It does
not delete the DID or its carrier trunks and does not restore the previous
carrier route. Reroute the number at DIDWW if you want calls to arrive
elsewhere. Reconnecting creates a fresh integration generation and rotates
credentials on its dedicated incoming trunk. Old incoming SIP credentials no
longer authenticate. Skysay blocks new calls through a disconnected number,
but disconnect does not delete your carrier trunks.

## Telnyx: connect with one API key

<Walkthrough id="import-a-number" tab="telnyx" />

You need an active voice number in your own Telnyx account and a published
AI agent if you want Skysay to answer incoming calls. Telnyx's account,
verification, balance and calling restrictions still apply.

<Steps>

<Step>

### Create a Telnyx API key

Sign in to your [Telnyx account](https://portal.telnyx.com/#/api-keys), open
**API Keys → Create API Key**, name the key Skysay and copy it. You will
paste it into Skysay in the next step.

</Step>

<Step>

### Choose Telnyx and list your numbers

Open **Numbers → Import a number**, choose **Telnyx**, paste the API key
and select **List my numbers**. Listing is read-only; it does not change
your number's route.

### What changes at Telnyx

Listing numbers is read-only. The API key grants account access; Skysay uses
it during each setup request and does not retain it. Calling authorization
is stored encrypted. You must enter the key again to retry or change setup.

Incoming setup changes only the selected number’s connection. Skysay creates
a dedicated TeXML application that securely connects the caller to your
AI agent. Existing number translation,
technical prefixes or forwarding can prevent safe setup; resolve those at
Telnyx before trying again. Avoid editing the route while Skysay connects it:
Telnyx cannot condition the routing update atomically on the previous value.
Messaging profiles are not changed, and this import does not connect SMS.

Outgoing setup creates a separate connection restricted to the selected
caller ID, one concurrent call, and Skysay’s configured voice-server IPs
plus a per-connection authentication token. It does not replace incoming
routing. Both incoming and outgoing setup require an enabled global outbound
voice profile, because Telnyx uses it to connect incoming calls to your AI
agent too. Skysay chooses a profile in this order: the existing dedicated
Skysay outgoing connection, the number’s current connection, then the sole
enabled global profile. Setup refuses if no eligible profile can be selected
unambiguously. Choose the intended profile before the first import. On retries,
changing the number’s current connection does not override an existing dedicated
Skysay outgoing connection’s profile. Skysay does not expand that profile’s
spending or destination permissions.

Telnyx continues charging number rental, carrier traffic and any applicable
programmable voice usage. Skysay charges
AI/platform usage at your workspace rates. Telnyx balance, account-level,
verification and destination restrictions still apply. A trial account can
reject a purchase or call even after you add credit. Importing does not
purchase a number or upgrade the Telnyx account.

The result reports incoming and outgoing setup separately. A configuration
check is not proof that a call has connected. Test both directions after
setup. If a request is interrupted, re-enter the same account’s API key and
recheck; Skysay reconciles recorded resources rather than creating duplicates
blindly. A changed or uncertain resource requires support.

**Disconnect from Skysay** blocks calls through this integration. It does not
delete the number, restore its prior route, or remove Telnyx connections.
Reroute the number at Telnyx to receive calls elsewhere. Delete its dedicated
Skysay outgoing connection at Telnyx to revoke that carrier authorization.
Reconnecting rotates authorization on the integration’s verified resources.

## DIDLogic

<Walkthrough id="import-a-number" tab="didlogic" />

Connect an active number you already own at DIDLogic. Skysay uses your
carrier API token to list your numbers and check their existing SIP setup.
DIDLogic continues billing the number and carrier traffic; Skysay charges
its applicable platform and AI usage.

Arrange the SIP setup with [Skysay support](mailto:support@skysay.ai) before
importing. Have your DIDLogic API token ready and keep enough credit in both
your carrier account and your Skysay workspace. The screenshots below use
a fictional example number and a masked example key.

<Steps>

<Step>

### Prepare the number at DIDLogic

Confirm that the number is purchased, active and approved for the calls you
want to make. In DIDLogic, configure:

- A dedicated SIP account with this number as its caller ID.
- The number's sole active incoming destination, pointing to the Skysay SIP
  address confirmed for your connection.
- The number's concurrent channel allowance and any required calling permissions.

DIDLogic's [SIP-account guide](https://docs.didlogic.com/docs/guides/getting-started/sip-credentials/)
explains its SIP account and caller-ID settings. Skysay support confirms the
destination and connection setup for your account. Updating this destination
changes where calls arrive, so review the routing change before applying it.

The import checks this existing setup. It does not create a DIDLogic SIP
account, replace the carrier destination or ask you for a SIP password in
this dialog.

</Step>

<Step>

### Choose DIDLogic and enter your API token

Sign in to your [DIDLogic account](https://app.didlogic.com/) and obtain its
API token. If API access is not enabled, ask DIDLogic support to enable it.
Use the token for the account that owns the number.

In Skysay, open **Numbers → Import a number**, choose **DIDLogic**, paste the
token into **DIDLogic API key** and select **List my numbers**. Listing reads
your carrier inventory; it does not purchase a number or change its route.

### Choose the number and confirm its type

be imported until DIDLogic activates them.

If a number is missing, check that the token belongs to the correct account
and that the number is active there. Contact Skysay support if your account
has more numbers than this list shows.

</Step>

<Step>

### Check whether setup is complete

**Number saved · setup pending** means Skysay verified ownership and saved
the number, but the existing setup did not pass every activation check. The
number is not ready to use in Skysay yet.

Ask Skysay support to check the SIP account, caller ID, incoming destination
and channel allowance with you. An invalid token or an unverified owner
produces an error instead; it does not reserve the number in your workspace.

</Step>

<Step>

### Recheck after correcting the setup

Once the carrier setup has been corrected, close the dialog and open
**Numbers → Import a number** again. Enter the same carrier account's token
and choose **List my numbers**. Select **Recheck** next to your pending
number. Skysay checks it again and updates that saved number.

### Connect your AI agent and test calls

**Number connected** means the required configuration checks passed at that
moment. It does not prove that a phone call has connected.

<img
  src="/docs-assets/images/docs/import-a-number/didlogic-result.webp"

Follow [Wire an agent to a number](/docs/wire-an-agent) to configure the
AI agent that handles calls. Place an incoming and an outgoing test call for
the directions your connection supports, and check that audio works both
ways. The carrier's balance, restrictions and permissions still apply.

</Step>

</Steps>

### DIDLogic billing, keys and supported services

DIDLogic bills its number rental and carrier minutes directly. Skysay bills
AI and platform usage from your workspace balance; it does not add managed
number rental for this imported number. Check **Billing** for your workspace
rates and usage.

The API token is used during setup and cleared when you finish or close the
dialog. Enter it again for a fresh listing or recheck. Keep carrier tokens
private; the documentation's example token is not a working credential.

This import connects **voice only**. SMS remains unavailable through this
connection even if your DIDLogic number supports SMS at the carrier. A saved
or connected number does not gain calling permissions that DIDLogic has not
approved. Contact support before changing or removing the carrier SIP setup
used by an existing connection.
