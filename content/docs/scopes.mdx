A scope is the unit of permission on a `sky_` key. The key is the boundary: tools
whose `required_scopes` are not present fail closed. Grant the fewest scopes an
agent needs.

## Scope catalog

| Scope | Grants |
| --- | --- |
| `account:read` | The key's own workspace context and workspace overview — wallet, agents, numbers, calls, SMS, usage. |
| `wallet:read` | Read the wallet balance and ledger, billing settings, invoices and the plan subscription. |
| `wallet:write` | Initiate owner-approved purchased-wallet top-ups with `create_wallet_topup` on full MCP. OAuth consent does not approve a payment or grant REST billing/settings access. With `numbers:write` it also authorizes or revokes carrier charges for [phone backup](/docs/phone-backup). |
| `coverage:read` | Coverage, number catalog, agent catalog, requirements. |
| `agents:read` | Read agents, the public agent catalog, and safe configuration such as voice stacks and workflow drafts. |
| `agents:write` | Create and configure agents; set voice stacks. |
| `knowledge:read` | List knowledge bases and their documents, read a document's extracted text, and test an answer against a knowledge base. |
| `knowledge:write` | Create, change and delete knowledge bases and documents, and attach knowledge bases to an agent. |
| `trial_calls:read` | List and read trial records: historical trial calls and offline trial fixtures. |
| `trial_calls:write` | Create offline synthetic trial fixtures; no live shared-number PIN calling. |
| `numbers:read` | List numbers, read number rules, list phone servers. |
| `numbers:write` | Request numbers, update rules, create/test phone servers. |
| `calls:read` | List calls, read call status. |
| `calls:write` | Place policy-gated outbound calls. |
| `recordings:read` | Read recording metadata, disclosure, and transcripts, including simulation conversation content. |
| `recordings:write` | Delete a call recording's transcript, AI summary and extracted results, and try to delete its stored audio (`DELETE /v1/calls/{call_id}/recording`); the call record stays. |
| `translations:write` | Request a translation of a call transcript (with `recordings:read`) or of an SMS message (with `sms:read`). |
| `sms:read` | Read SMS conversations and message text. |
| `sms:send` | Send policy-gated SMS. |
| `policy:evaluate` | Evaluate outbound policy and authorize outbound. |
| `onboarding:read` | Read the workspace capabilities. |
| `onboarding:write` | Request workspace capabilities. |
| `api_keys:read` | List API keys and read the grant catalogue (`GET /v1/api-keys/scopes`). |
| `api_keys:write` | Create and revoke API keys. |
| `gateways:read` | List and read self-hosted gateway deployments, and list their tokens. |
| `gateways:write` | Create gateway deployments, issue and revoke their tokens, and set their outbound mode and content storage. |
| `usage:read` | Read the usage summary, usage records, and daily and monthly usage. |
| `audit:read` | Read the workspace's audit events (`GET /v1/audit-events`). |
| `simulation_suites:read` | Read one Simulations Lab run's results for a build server, without the agent's configuration. |
| `team:read` | Read the member list on the workspace's Team page; no public API route uses it. |

Content scopes are enforced field by field. A tool that mixes content with
other data, such as `send_sms` or `get_simulation_run`, stays callable at its
base scope and omits SMS text or conversation content without `sms:read` or
`recordings:read`. `account_overview` never includes SMS message content. Subscribing a webhook to
`sms.received` or `call.extraction.ready` needs the matching content scope, and
changing a webhook address needs both. See [Content fields](/docs/mcp#content-fields).

## Prefix scopes

A prefix scope covers every leaf under it. `sms:*` grants both `sms:read` and
`sms:send`; grant the leaf for least privilege, the prefix when the whole group
is genuinely needed.

## API keys and OAuth grants

A delegated agent key cannot self-grant billing or control-plane permissions.
Requested API-key scopes are clamped server-side to what the minting credential
holds; workspace keys exclude `operator:*`, `worker_jobs:read`,
`worker_jobs:write` and `provider_mutations:*`.
An authorized workspace API key can carry `wallet:write`, so keep its billing
access out of a delegated key unless needed.

OAuth grants are separate from API-key delegation. A full MCP connection can
receive `wallet:write` through consent; it is offered ticked, and can be
unticked, when neither requested nor already granted. That OAuth token works only on MCP,
not REST billing or settings routes. Each top-up still needs separate owner
approval of the exact amount, currency and purpose. The read-only connector
cannot receive this payment permission. See [OAuth permissions](/docs/mcp#permissions-consent-and-reconnecting).

## Fail-closed

<Callout title="No partial execution">
  A `tools/call` for a tool whose `required_scopes` are missing returns
  `missing MCP scopes: X` and does nothing. There is no best-effort fallback.
  Every call is also pinned to the key's organization — a mismatched
  `organization_id` is rejected with `MCP organization mismatch`.
</Callout>

See [Authentication & keys](/docs/authentication) for minting, rotating, and
revoking keys.
