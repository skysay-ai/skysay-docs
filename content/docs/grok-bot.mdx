## Option 1: Let Grok Bot set up a new account

<Callout type="warn" title="Release acceptance pending">
This new-account flow is being prepared for the matching backend release. Do not
use it until the headless endpoints are enabled. The manual OAuth connection
below remains available. A successful local backend test does not certify a new
connection in every Grok Bot version.
</Callout>

Paste this into a fresh Grok Bot that has no authorized Skysay connection:

```text
Read https://skysay.ai/docs/grok-bot and set up a new Skysay account for me.
Ask for my phone number, email, full country name, and optional city or area
code. Confirm that I accept Skysay's terms before starting. Use the headless
signup API with client_name "grok", then ask me for the texted verification code.
Never log my code, signup session, API key, payment token or card details.

Start with the single $5 setup credit and do not pay for anything without my
separate approval. Show the selected number's setup and monthly prices and
carrier requirements. Request a matching local number only when its initial
cost leaves enough setup credit for the test call; otherwise show alternatives
and ask before any payment. A number request is not an active number. Wait for
activation and verify outbound capability before calling.

Store the returned key only in a secure custom MCP connection credential field
for https://api.skysay.ai/mcp. Prove this NEW connection with account_overview.
If this Grok version cannot add a new connector securely, stop and tell me what
must be configured. Do not reuse another account-wide connection as proof.

Create and publish a suitable hosted voice agent using the supported metered
catalog. After I approve the caller number, destination and task, place one
setup test call to the phone I verified, for at most 60 seconds. Read the final
call result; do not claim an answered or completed call from a call ID alone.
Outside the United States, Canada, United Kingdom and Mexico, outbound calls
and SMS need carrier review and depend on number type. Do not promise them.

If I later approve payment, use the documented Stripe hosted checkout for a
Link virtual card, or request the server's amount/currency/seller profile and
use an owner-approved Link shared payment token. Never send a card number to
the Skysay API. An uncertain payment must be retried with the same key and
credential. Check the wallet after its signed Stripe webhook. The trial does
not approve ongoing number fees or paid call overage.
```

Connect Grok Bot to hosted Skysay MCP to check coverage, request a number,
place calls through a Skysay voice AI agent and send supported SMS. No local
bridge or downloaded server is needed. Grok Bot plans the task; the configured
voice AI agent speaks on the telephone.

**Works outside the US:** Skysay offers numbers in **100+ countries**, including
the United Kingdom, Germany, Brazil, Argentina and Australia. Outside the
United States, Canada, United Kingdom and Mexico, local numbers receive inbound
calls immediately once active; **outbound calls and SMS need a carrier review
first**. A listed country does not mean every channel is ready to use.

Setting up a different assistant? See [Connect an MCP client](/docs/install-connector).

## Prerequisites

- Grok Bot with a custom remote MCP connection that supports OAuth or a securely
  stored bearer credential. New-account setup must establish a genuinely new connection.
- For manual connection, a [Skysay workspace](https://skysay.ai) and permission to connect it.
- The headless flow requires a real phone that can receive a texted OTP and a new
  verified phone. The email is unverified contact data, is not unique, and cannot
  sign in, recover the workspace or link an existing email account. The single $5 grant
  can cover an eligible initial number and one hosted test call to the verified
  owner, within its cap. Other PSTN calls, SMS and renewals require approved
  purchased funds. A requested country may have no number affordable within the
  cap. See [Billing](/docs/billing).

Connecting a server does not activate a number or authorize spending. Start
with a successful read, then enable only the actions you need.

## What Grok Bot does

1. **Start phone verification.** Call `POST /v1/agent/onboarding/headless/start`
   with `phone`, `email`, `country`, `client_name: "grok"`, `terms_accepted: true`
   and optional `city`/`area_code`. Inventory is checked before a text is sent.
   A `409` includes bounded country alternatives when matching inventory is
   unavailable. Existing identities must use normal sign-in; SMS never takes
   over an existing account.
2. **Ask for the code.** Call `POST /v1/agent/onboarding/headless/complete` with
   `headless_session` and the six-digit `otp_code`. Sessions last ten minutes,
   allow five guesses and complete once. The response includes the workspace,
   project, one-time API key, MCP connection fields and the bounded setup-credit
   terms. Phone verification owns the workspace; email is unverified contact only.
   Email login cannot inherit this workspace. Future dashboard linking would
   require proof of both identities and explicit consent; it is not available
   through this setup flow.
3. **Connect and prove access.** Add the returned bearer key using the client's
   secure credential controls and run `account_overview`. The endpoint is
   Streamable HTTP. Returned connection details do not prove Grok installed or
   authenticated the connection. Never paste the key into a public prompt.
4. **Choose and request the number.** Read the canonical number catalog and exact
   inventory for the requested country/location. Submit its opaque inventory
   row ID as `available_number_id` to
   `POST /v1/agent/onboarding/headless/number`. The ordinary price, identity,
   carrier, routing and capacity gates still apply. Poll the returned request
   until the number is active; a pending request is not a usable line. More
   expensive numbers require separate approval and the normal paid order path.
5. **Approve and check one owner test.** Configure and publish a supported
   metered hosted voice agent, verify the number's outbound readiness and ask
   the owner to approve the task. Use `create_outbound_call` with a stable
   idempotency key and the verified owner's phone as the destination. Eligible
   setup calls have a 60-second ceiling and use the remaining promotional
   credit. Other destinations cannot spend it. The trial does not charge a
   saved card or turn a cost overrun into customer debt. Check `get_call` and,
   when available, the transcript before reporting what happened.

### Optional payment after the free start

Use `POST /v1/agent/onboarding/headless/payments` with an owner-approved amount
in the wallet currency, a stable `idempotency_key` and `payment_approved: true`.

- **Link virtual card:** select `method: "card_checkout"`. The returned Stripe
  hosted checkout accepts a virtual card through its normal form. Stripe and
  the issuer still validate the payment and may require further approval.
  Card numbers never go through Skysay's API.
- **Shared payment token:** select `method: "shared_payment_token"` and first
  set `request_challenge: true`. The `402` response supplies the current amount,
  currency and `stripe_profile_id`. Request an SPT for those exact values using
  Link CLI's `spend-request create --credential-type shared_payment_token
  --network-id <stripe_profile_id> --request-approval`, then retry with
  `shared_payment_token`. This endpoint uses a JSON challenge, not the MPP wire
  protocol; do not substitute `link-cli mpp pay`.

A synchronous success is not wallet credit. Wait for the signed Stripe webhook
and check the wallet. On an uncertain result, reuse the same payment key and
credential instead of approving another charge. Neither top-up nor setup credit
alone opts a trial number into renewal: after a successful approved payment,
use `POST /v1/agent/onboarding/headless/number/renewal-approval` with
`renewal_approved: true` only after the owner separately approves ongoing fees.

Exact schemas and errors are in [API reference](/docs/api-reference).

## Option 2: Configure the connection yourself

Ask Grok Bot to add a custom remote MCP server named Skysay with the values
below. Complete the connection card's sign-in flow if it appears. To inspect an
existing connection, open **Connect apps → Your plugins → Skysay** and check
the URL and connected status. Installed connectors are shared across your
account's Bots, so a fresh Bot can use an existing authorized connection.

If the connection cannot be added or authenticated, stop and use a
[supported MCP client](/docs/install-connector) instead of pasting a secret
into chat. See [Grok Bot's app connection guide](https://docs.x.ai/grok-bot/computer-and-apps#connect-an-app).

| Field | Value |
| --- | --- |
| Server URL | `https://api.skysay.ai/mcp` |
| Transport | Streamable HTTP |
| Authentication | OAuth authorization code with PKCE S256 |
| API-key alternative | `Authorization: Bearer YOUR_SKYSAY_API_KEY`, only in a secure connection credential field |
| Fixed read-only resource | `https://api.skysay.ai/mcp/read-only` |

For API-key setup, [create a scoped workspace key](/docs/authentication).
Never paste it into a conversation or commit it. For OAuth, review the requested
permissions before consenting. Start the workspace read with `account:read`;
add `coverage:read` for the coverage checks and the specific write scopes only
when you decide to enable those actions. See [Scopes](/docs/scopes).

Then ask Grok Bot:

```text
Use Skysay account_overview and summarize the result.
Do not perform writes, place calls or send SMS.
```

The fixed read-only resource has five workspace read tools and deliberately
excludes coverage checks and writes. Its OAuth resource and token are separate
from the full endpoint; reconnect when switching resources.

## Coverage and limits

Numbers are available in 100+ countries. Always check live `get_coverage` and
`get_number_catalog` results for the country and number type you want.

| Country examples | Inbound calls on an active local number | Outbound calls and SMS |
| --- | --- | --- |
| United States, Canada, United Kingdom, Mexico | Available | Check the number's channels, workspace readiness and any messaging registration first. |
| Germany, France, Spain, Italy, Poland | Available immediately once active | Carrier review required first; do not assume either channel is enabled. |
| Brazil, Argentina, Australia | Available immediately once active | Carrier review required first; do not assume either channel is enabled. |
| Belgium, Switzerland | Available immediately once active | Carrier review required first; SMS also depends on the number type. |
| United Arab Emirates | Check toll-free availability and business registration | The public UAE toll-free offer is inbound voice only. |

Number availability and activation requirements vary. "Inbound immediately"
describes an active number's capability, not an instant-purchase guarantee.
Workspace outbound approval and a number's carrier review are separate checks;
neither makes every number SMS-capable.

**Costs:** pay as you go has no monthly platform fee. Number rental, setup,
carrier minutes, hosted voice AI and SMS are charged separately. Use the quote
shown before assignment or use and the [public pricing page](https://skysay.ai/pricing).

**Workspace limits:** pay as you go supports up to **10 simultaneous calls**
and **10 billed numbers**. Workspace risk limits and carrier capacity may be
lower. `get_capabilities` shows current channels, destinations, caps and usage.
For higher limits, [contact Skysay](https://skysay.ai/contact).

Calls also have duration and silence controls. See
[How a call ends](/docs/how-calls-end). Before each outbound action, check
[Policy & outbound](/docs/policy-and-outbound). A refusal needs the named
readiness issue resolved; do not retry it automatically.

## Things to ask Grok Bot

Start with an approved caller number, a configured voice AI agent and a
destination you own or whose recipient agreed to the call. For example:

```text
Check my UK number's outbound readiness and my voice agent's English setup.
Prepare one short test call to the number I provide. Show me the caller,
recipient, task and expected cost, and wait for approval before dialling.
Afterwards, report the terminal status and transcript if available.
```

Once you have tested that path, adapt the task:

```text
Prepare a call to a restaurant in Madrid in Spanish to ask about a table for
4 on Friday at 21:00. Use my approved outbound-capable number and a published
Spanish voice agent. Show me the recipient, instructions and cost first.
Instruct the agent to ask about availability only and not confirm a booking or
alternative date. Report back so I can decide what to approve next.
```

```text
Check whether my number can send SMS. Prepare this text to the recipient I
provide: "Hi Maria, see you Wednesday at 10. Reply if anything changes."
Show me the sender, recipient, exact message and cost before sending.
```

```text
Help me assign a published inbound voice agent to my active Berlin number
to take messages while I am busy. Show me the configuration before changing
it. Do not enable outbound calls or SMS without the required carrier review.
```

Recurring reminders need a separately configured scheduler. Receiving calls
needs an assigned inbound agent; a post-call SMS summary needs a separate
automation and an SMS-capable, approved sender. These examples do not set
those automations up automatically.

The approval instructions are for your assistant; OAuth does not enforce a
human confirmation for every billable tool call. Follow the
[billable-action controls](/docs/quickstart#before-any-billable-action), including
recipient consent, AI disclosure and recording requirements for your use case.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Connected, but no tool result | Ask for `account_overview`; a saved connection alone proves nothing. |
| HTTP 401 or sign-in loop | Complete OAuth again, or check the key. Tokens for the two MCP resources are separate. |
| Coverage tool refused | Use the full `/mcp` resource with `coverage:read`. |
| Call or SMS refused | Read `get_capabilities` and the number's rules; carrier review, channel support, funds or caps may block the action. |
| Number request waits | Check the request status and required documents. For an assigned number, `get_number_rules` explains its rules. |
| Call ID returned, but no answer | Read the call status and evidence before claiming success. |
