Phone backup is an optional safety net for a Skysay number that an AI agent
answers. When the AI cannot take a call, Skysay connects the caller to a phone
number you chose, such as your office or an on-call mobile. No AI agent joins
that call, so there is no recording, transcript, summary or AI charge. You pay
the two carrier legs of the call and nothing else.

Backup is off until you turn it on for a number, and it does nothing on a
phone connection Skysay has not enabled for it.

## When backup is used

Skysay offers the call to your team phone in two situations only:

- **Every phone line is busy.** The call arrives while every agent line on the
  platform's phone host is already in a call. Without backup the caller hears a
  busy signal and the call is recorded as failed with
  `inbound_capacity_reached`; see [Failure reasons](/docs/post-call-results#verify-every-delivery).
- **The number's AI setup cannot run.** The agent's published configuration
  cannot build a conversation, for example because a voice, model or
  instruction is missing. Without backup the call is refused with one of the
  [configuration reasons](/docs/post-call-results#when-the-configuration-could-not-be-run).

Pausing the AI agent does not trigger backup, and neither does a call that a
policy check refuses. Before every backup call Skysay checks again that your
authorization, available funds, phone permissions and workspace limits still
allow it. If any check fails, the call is handled exactly as it would be with
backup off.

## What a number needs

Backup can be authorized only when the number's saved routing is ready:

- **An AI agent answers it.** Routing is set to answer with a Skysay AI agent
  that is enabled.
- **A separate team number is saved.** Add the team phone number as the
  number's fallback in **Advanced call policy**. It must be a different phone
  number: not a Skysay number and not a number that forwards back to Skysay.
- **Recording is off.** Backup calls are not recorded, so turn recording off in
  **Advanced call policy** and save before authorizing.
- **The number is active.**

Authorization also depends on the phone connection the call arrives on.
Skysay enables backup per connection. On a connection that has not been
enabled, the Numbers page shows **Connection not configured** and no backup
call is placed, even when you have authorized it.

## Turn it on in the workspace

1. Open **Numbers** and select the number.
2. In **Phone backup**, check that the team number shown is the one you want.
3. Select **I authorize carrier charges for calls to this backup number**, then
   **Authorize phone backup**.

The badge changes to **Charges authorized**. Select **Revoke authorization** at
any time to stop backup for that number. Changing the number's saved routing or
its team number cancels the authorization: the page shows **Not authorized**
until you review the new details and authorize again. **Add funds**, next to
the button, opens billing; on a connection that is not enabled it reads **Ask
support** instead.

## Turn it on with the API

Read the current permission with `GET /v1/numbers/{number_id}/backup-authorization`
(`numbers:read`). Authorize or revoke it with
`POST /v1/numbers/{number_id}/backup-authorization`, which needs both
`numbers:write` and `wallet:write`. Treat a key with `wallet:write` as able to
spend your funds. Both operations take an optional `project_id` (a query parameter on `GET`, a
body field on `POST`), are limited to your workspace, and place no call and
reserve no money. The generated
[API reference](/docs/api-reference) lists the exact fields.

```bash
curl -s "$SKYSAY_BASE_URL/v1/numbers/$NUMBER_ID/backup-authorization" \
  -H "Authorization: Bearer $SKYSAY_API_KEY"
```

```json
{
  "number_id": "num_2XbK7pQw4ZrT9mNc",
  "route_id": "nr_8HcV3tLq1YfN6pRa",
  "generation": 0,
  "authorized": false,
  "state": "not_authorized",
  "destination_e164": "+15550142",
  "terms_revision": "carrier-backup-1",
  "authorized_at": null,
  "unavailable_reason": "needs_confirmation"
}
```

`destination_e164` is the team number saved on the number's routing.
`unavailable_reason` is empty once backup is authorized. Otherwise it says why
authorization is not possible yet, or that routing is ready:

| `unavailable_reason` | Meaning |
| --- | --- |
| `route_unavailable` | The number has no saved routing to authorize. |
| `not_configured` | Routing is not set to an AI agent, or no team number is saved. |
| `recording_enabled` | Recording is on; backup calls are not recorded. |
| `number_unavailable` | The number is not active. |
| `needs_confirmation` | Routing is ready and has not been authorized yet. |

To authorize, send the values you just read. The request is refused unless each
one still matches:

```bash
curl -s -X POST "$SKYSAY_BASE_URL/v1/numbers/$NUMBER_ID/backup-authorization" \
  -H "Authorization: Bearer $SKYSAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "expected_generation": 0,
    "expected_route_id": "nr_8HcV3tLq1YfN6pRa",
    "request_key": "backup-office-line-1",
    "accept_charges": true,
    "destination_e164": "+15550142",
    "terms_revision": "carrier-backup-1"
  }'
```

- `accept_charges` is `true` to authorize carrier charges and `false` to revoke.
  Authorizing is the consent: nothing is charged by sending it.
- `destination_e164` must be exactly the team number now saved on the number,
  and `terms_revision` must be the current `terms_revision` the `GET` returned.
  Revoking needs neither.
- `expected_generation` and `expected_route_id` name the state you reviewed.
  Each accepted authorize or revoke adds one to `generation`. If a colleague changed the
  routing, the team number, the terms or the authorization in the meantime, the
  request fails with `409` and nothing changes, so read again and decide again.
- `request_key` is 8 to 100 letters, digits, `_` or `-`. Sending the same key
  with the same content again returns the saved result with `idempotent: true`.
  Reusing a key for different content fails with `409`.
- Authorizing is also refused with `409` while routing is not ready, that is
  while `unavailable_reason` is `route_unavailable`, `not_configured`,
  `recording_enabled` or `number_unavailable`.

`400` means a field is invalid or unknown, `403` a missing scope or workspace
authority, and `404` a number or project outside your workspace. A granted
authorization does not promise a call will connect: the checks in
[When backup is used](#when-backup-is-used) run again for every call.

## What happens on a backup call

1. The call arrives and Skysay cannot hand it to the AI.
2. Skysay checks the number, your authorization and your funds, and holds funds
   for the call (see [Pricing](#pricing)).
3. Skysay dials your team number once, presenting your Skysay number as the
   caller ID. The team phone rings for at most 30 seconds, counted from when
   the incoming call arrived.
4. If your team phone answers, the two are connected until either side hangs up
   or the call reaches 30 minutes.

If your team phone is busy or does not answer, the call ends. Skysay does not
retry, try another number, play a message or take a voicemail. Backup is not a
voicemail service.

## Limits

- **One backup call per number at a time.** While a backup call is active on a
  number, another caller to that number is handled as if backup were off. A
  call that has just ended, for example because the caller hung up while the
  team phone rang, can keep the number's backup in use for a short while before
  it is released.
- **30 seconds of ringing** at the team phone, and **30 minutes** of call.
- **One dial per call.** There is no automatic second attempt.
- **Workspace limits still apply.** Backup is not used when your workspace's
  concurrent-call limit is reached, and the call to the team number follows
  your outgoing-call approval and country rules.

## Pricing

A backup call has two carrier legs, each billed by the started minute:

- **The incoming leg**, the caller's call into your Skysay number, at that
  number's incoming-call price.
- **The backup leg**, Skysay's call to your team number, at the outgoing price
  for that destination.

There is no AI, voice or recording charge. Prices differ by number and
destination, and the call's detail shows the price of each leg.

Before dialing, Skysay holds funds for both legs for the longest a backup call
can run: 30 minutes plus ringing time and a short margin, shown on the call as
33 minutes for each leg. A hold sets money aside; it is not a charge. After the
call ends, Skysay settles each leg from its own record and returns the unused
part. If your available funds cannot cover the hold, no backup call is placed.
See [Billing](/docs/billing) for how holds and balances appear.

## Limitations

Read these before relying on backup for calls you cannot miss.

1. **The caller is answered as soon as the backup dial starts.** Skysay answers
   the incoming call when it begins dialing your team phone, not when the team
   phone answers. While the team phone rings, the caller hears silence rather
   than ringing, and Skysay plays no message. If the team phone is busy or does
   not answer, the incoming call has still been answered, so it counts as a
   connected incoming call and can be charged as one.
2. **Backup trusts the connection it arrives on.** Skysay acts on the caller and
   called numbers that an enabled carrier or phone-system connection reports,
   and cannot verify them independently. For that reason backup is offered only
   for onboarded, trusted connections. Anyone able to send calls over such a
   connection can cause backup calls to your team number, within the limits
   above, and you are charged for them.
3. **An unanswered backup can leave part of the hold reserved.** When the team
   phone never answers, Skysay may not know exactly when the incoming call
   ended. The incoming leg is charged when its times are known, and the rest of
   the hold is released by a reconciliation. Skysay does not promise when that
   reconciliation runs. Until then the call shows as not charged yet with the
   reserved amount held. If an ended call still shows a reserved amount, contact
   support with the call ID.

## Read the call on the Calls page

A backup call appears in **Calls** like any incoming call, with no AI agent
and no recording or summary. Its status is one of:

| Status | Meaning |
| --- | --- |
| **Dialing** | Skysay is calling your team phone. |
| **Completed** | The team phone answered and the call ended. |
| **Busy** | The team phone was busy. |
| **No answer** | The team phone rang and was not answered. |
| **Canceled** | The caller hung up before the team phone answered. |
| **Failed** | Skysay could not place or complete the backup call. |

The cost column shows the charge once both legs are settled. Until then it
reads **Not charged yet** with the reserved amount, which is a hold and not the
final price. Open the call to see each carrier leg's rate, the reserved,
charged and released amounts, and any amount due.

If the caller hangs up while the team phone rings, the call can keep showing
**Dialing** for a short while before it settles as **Canceled**.
