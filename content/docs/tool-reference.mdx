Every tool the agent can call, with the scope it requires. Scopes are
authoritative on the server's tool-scope table — treat
the live `tools/list` on your instance as canonical. Required scopes are published
under `_meta["ai.skysay/required_scopes"]`, with alternatives under
`_meta["ai.skysay/alternative_required_scopes"]`. Read tool responses from
`result.structuredContent` and check `result.isError`; see the
[MCP client migration guide](/docs/mcp#migration-for-custom-mcp-clients).

## Account

| Tool | Scope | Description |
| --- | --- | --- |
| `account_overview` | `account:read` | Bounded workspace summary: wallet, usage totals with up to 10 line items, and for agents, numbers, number requests, calls and SMS conversations a `total` with up to 5 newest previews and the `list_tool` that pages them. Never includes SMS message content. See [Bounded results and paging](/docs/mcp#bounded-results-and-paging). |
| `list_audio_environments` | `account:read` | Read the immutable versioned ambience catalogue (including Off). It has the same result and scope as `GET /v1/audio-environments`; it never contacts a provider or changes a selection. |
| `get_workspace_context` | `account:read` | The workspace your credential belongs to and a page of its projects (id, name, environment), oldest first (`limit` 1–100, default 50; `offset`). Tools that ask for `project_id` take one of these ids; it works before the workspace has any agent. |
| `get_activation_state` | `account:read` | The workspace's set-up checklist: eight steps, whether each is done, and the next step with what to do. With `project_id`, agents, numbers, number orders, SMS conversations and calls are counted for that project only. |
| `create_wallet_topup` | `wallet:write` | Initiate an explicitly owner-approved purchased-wallet top-up for the authenticated workspace: return a direct Stripe Checkout URL, or use a compatible wallet’s approved shared payment token. Permission alone approves no payment; see [funding paths and limits](/docs/billing#adding-funds-through-mcp). Absent from the read-only connector. |
| `create_topup_checkout` | `wallet:write` | Open a Stripe checkout page for the workspace owner; this tool moves no money. When Stripe top-ups are on, the answer carries the page's checkout_url; otherwise it says they are disabled or not configured, and no page is made. Nothing is charged until a person pays on that page, and only Stripe's signed confirmation then adds amount_minor (the wallet currency's minor units, within the server's top-up bounds) to the wallet as credit. With number_request_id (needs numbers:read too), the page is for a number order waiting for payment and returns to that order; once the wallet covers the order's first charge, fulfilment starts, and get_number_request shows it. success_url, cancel_url and idempotency_key are then not used. Without idempotency_key, an unpaid page for the same amount is returned again while Stripe can still take payment on it, inside the reuse window (15 minutes by default) and after it, when it was opened for the same order and return pages; for another order or other return pages the new one is refused (ConflictError) until that page can no longer be paid. Absent from the OpenAI connector, like `create_wallet_topup`. |

When enabled with live conversations on, visitors can start conversations billed to the workspace. |
| `list_agent_public_link_recording_candidates` | `agents:read`, `recordings:read` | List one page of an AI agent's calls that can be shared as recorded conversations on its public link, and why a call cannot be shared yet. |

| `preview_voice` | `agents:write` | Explicit bounded, rate-limited provider/BYOK Listen action; may have provider and safe state effects, so it is not read-only. |
| `get_agent_variables` | `agents:read` | Read an AI agent's [call variables](/docs/call-variables) config with its `revision` and `schema_hash`; the same answer as `GET /v1/agents/{agent_id}/variables`. |
| `set_agent_variables` | `agents:write` | Replace an AI agent's whole call variables config, checked and republished at once. Send `base_revision` to be refused rather than overwrite a newer write. A refused config returns `error.body.issues`. |
| `get_agent_post_call_extraction` | `agents:read` | Read an AI agent's [result fields](/docs/post-call-results): the schema of what is written down after each of its calls, and whether it is on. |
| `set_agent_post_call_extraction` | `agents:write` | Set or switch off an AI agent's result fields, the same as `PATCH /v1/agents/{agent_id}/post-call-extraction`: 1 to 24 scalar fields, a new schema version for later calls; the active schema sent again changes nothing. |
| `send_agent_chat_turn` | `agents:write` | Send one text message to a hosted AI agent and read its reply, as the workspace's chat test does: the agent as a call would run it, without audio. Nothing is saved and no call is made; tools other than knowledge search and `end_call` are held, not performed. |
| `generate_agent_identity` | `agents:write` | Write an AI agent's instructions, first message and result fields from a template, the agent's name, your notes, the opening language and the text of ready knowledge documents. Naming `knowledge_document_ids` also needs `knowledge:read`. |
| `duplicate_agent` | `agents:write` | Create an independent, stopped copy of an AI agent from its latest saved settings. The copy is not published and has none of the original's calls or history. Reuse `request_key` and `name` after an uncertain result. Connection secrets are never returned by this tool. |
| `check_agent_deletion` | `agents:read` | Read what currently prevents an AI agent from being deleted. The check reserves nothing; `delete_agent` checks again. |
| `delete_agent` | `agents:write` | Permanently remove one unused AI agent. Refused while it has numbers, routes or unfinished work. Its past calls, transcripts and billing are kept, and no number is cancelled. Ask the user to confirm before calling. |

| --- | --- | --- |
| `list_numbers` | `numbers:read` | Bounded newest-first `{ numbers, pagination }` page of phone numbers with registration status and `when_called`, what each number does when called (`limit` 1–50, default 10; at most 25,000 characters). |
| `get_number_rules` | `numbers:read` | Read who answers calls to one phone number (`incoming.when_called`) and its outgoing and recording rules. |
| `list_phone_servers` | `numbers:read` | List the workspace's phone servers: your own PBX or media servers that a number's calls can be sent to. |
| `request_number` | `numbers:write` | Create a managed number request (live ordering can need operator approval). Like an order placed through `POST /v1/number-requests`, it is marked as needing verification where the number's market requires it, and it records the connected credential as its requester. |
| `update_number_rules` | `numbers:write` | Set who answers calls to one phone number: an AI agent, your phone server, a forward to a phone number, or no answer ([choose who answers a number](/docs/mcp#choose-who-answers-a-number)). Also its outgoing and recording rules. The change is recorded under the connected credential, whatever `actor_type` or `actor_id` the arguments carry. |
| `create_phone_server` | `numbers:write` | Add a phone server: your own PBX or media server that a number's calls can be sent to. It reads `not_tested`; `update_number_rules` sends a number's calls only to a verified one, and no tool can verify one yet. Any input outside the tool's schema is refused. |
| `list_available_numbers` | `numbers:read` | List the exact numbers loaded for purchase, at most limit (default 100, at most 250), with each one's customer price and has_more. A row is a snapshot, not a reservation: availability and price are checked again with the carrier when the number is ordered. When nothing is loaded for a market, load it with search_available_numbers; order one with request_number. |
| `search_available_numbers` | `numbers:write` | Load exact numbers from the carrier for one country and number type (default local), optionally narrowed by area code or region, and return at most limit of them (default 10, at most 20). Nothing is reserved, ordered or charged. A recent identical search is answered from the loaded numbers instead of asking the carrier again. Refused while the workspace's numbers are suspended. |
| `get_number` | `numbers:read` | Read one phone number of the workspace: the record list_numbers shows, without when_called (who answers it: get_number_rules). |
| `get_number_activation` | `numbers:read` | Read whether a number is active, and if not, what blocks it (for example verification still pending or information still needed) and what the customer can do. |
| `list_number_requests` | `numbers:read` | List the workspace's number orders, newest first, a page of at most limit (default 50, at most 100), each with its status, the message and next step for the customer, and the number once one is assigned. Pass pagination.next_cursor as cursor for the next page. |
| `get_number_request` | `numbers:read` | Read one number order: its status, the message and next step for the customer, and the number once one is assigned. |
| `update_number_request` | `numbers:write` | Change the customer's own fields of a number order: customer_reference, preferred_phone_number (a wish shown with the order; it reserves nothing) and requested_capabilities. Fields that are sent replace the stored ones. Status, price and fulfilment are Skysay's and cannot be changed here. |

## Call forwarding

[Keep your number](/docs/keep-your-number): your own phone provider forwards calls from your existing business number to a Skysay number that an AI agent answers. No tool changes carrier settings, buys a number or places a phone call, and a forwarding condition is verified only by linked call evidence. `project_id` is optional and defaults to the workspace's first project.

| Tool | Scope | Description |
| --- | --- | --- |
| `list_forwarding_setups` | `numbers:read` | List a project's call forwarding setups, newest first, 100 per page; `offset` continues the list. |
| `create_forwarding_setup` | `numbers:write` | Create a setup; the same `idempotency_key` returns the same setup. A draft can be unfinished: `source_number` is your existing business number, `conditions` say when calls are forwarded (busy and unanswered unless chosen), `number_id` and `agent_id` are the Skysay number and the AI agent that answer them. |
| `get_forwarding_setup` | `numbers:read` | Read one setup and its `revision`, which a change, a report and the start of a test take as `base_revision`. |
| `update_forwarding_setup` | `numbers:write` | Change a setup; `base_revision` must be its current revision. Changing a number, the AI agent, the line type, the provider or the conditions cancels a watching test. After the instructions were recorded, the two phone numbers cannot be changed until `record_forwarding_stop`. |
| `get_forwarding_instructions` | `numbers:read`, `agents:read` | Whether the setup is ready and, once it is, what to ask your phone provider for: the Skysay number to forward to and the conditions, with example codes your provider has to confirm. `instructions` is `null` until then. |
| `record_forwarding_instructions` | `numbers:write` | Record that you report having set forwarding with your phone provider. Refused until the setup is ready. It is your report, not a verification. |
| `record_forwarding_stop` | `numbers:write` | Record that you report having stopped forwarding with your phone provider. It cancels a watching test. |
| `start_forwarding_test` | `numbers:write` | Start a three-minute watch for a test of one of the setup's conditions. Skysay places no call: from another phone you call your existing business number and, when the AI agent answers, enter the six-digit `challenge` from this answer on the keypad. Refused until the instructions were recorded for the current setup, and while another test of the setup is watching. For an unchanged setup the same `idempotency_key` returns the same test. |
| `get_forwarding_test` | `numbers:read`, `calls:read` | Read one test: `status` is `watching`, `received_unconfirmed` (the call arrived and the code matched, which alone does not verify the condition), `verified`, `cancelled` or `expired`. It does not repeat the challenge; `start_forwarding_test` does, for the same `idempotency_key`, while the test is watching. |
| `cancel_forwarding_test` | `numbers:write` | Stop a test that is still watching. |

## SIP connections

[Bring your own SIP trunk](/docs/bring-your-own-sip-trunk). These tools are for numbers on your own carrier SIP trunk; who answers any number is set with `update_number_rules`. No tool changes carrier settings. Passwords are write-only and never returned. `project_id` is optional and defaults to the workspace's first project.

| Tool | Scope | Description |
| --- | --- | --- |
| `list_sip_connections` | `numbers:read` | List a project's SIP connections, newest first, 20 per page; `offset` continues the list. |
| `create_sip_connection` | `numbers:write` | Save your carrier trunk with one generic form. Saving admits the inbound source networks to the Skysay SIP edge automatically once a number is attached for incoming calls. |
| `get_sip_connection` | `numbers:read` | Read one connection: its settings and checks, and its attached numbers, 50 per page, each with its latest ownership check and test call; `offset` continues the numbers. |
| `update_sip_connection` | `numbers:write` | Replace the connection's settings. Send `expected_revision`. Omit a password to keep the stored one; changing a username needs its password again. Changing the source networks or the carrier host requires every number's ownership to be confirmed again. |
| `disable_sip_connection` | `numbers:write` | Disable the connection for good: its numbers are detached, and it cannot be changed or enabled again. This is not the pause for unusual call volume, which `resume_sip_connection` ends. |
| `resume_sip_connection` | `numbers:write` | End a pause for unusual call volume early. Up to three times a day per connection. If the connection trips again within a day, it pauses for the next, longer window (10, then 30, then 60 minutes). |
| `attach_sip_connection_number` | `numbers:write` | Attach a number you hold at your carrier. Attaching it for incoming calls places one Skysay verification call to the number that plays a one-time code (rate limited per number and per workspace); ownership is confirmed when the code is heard on that call arriving on this connection. Outbound calls with this number as caller ID are refused until then. A number can be attached to one connection in all of Skysay. |
| `detach_sip_connection_number` | `numbers:write` | Detach the number. It stays in your workspace, not connected, and can be attached again. |
| `check_sip_connection_number_ownership` | `numbers:write` | Place one more verification call to the number. Rate limited per number and per workspace. Outbound calls with the number are refused until its ownership is confirmed. A number attached for outbound only cannot be confirmed by a call; contact support. |
| `get_sip_connection_ownership_check` | `numbers:read` | Read one ownership check of a number: one verification call and its result. |
| `check_sip_connection_reachability` | `numbers:write` | Ask Skysay's SIP host to send one SIP OPTIONS to your carrier's server. The answer shows on the connection under `checks.reachability` within about a minute. It shows whether the server answers, not that calls work. Rate limited per connection. |
| `start_sip_connection_test_call` | `calls:write`, `numbers:read` | Place one ordinary call from this number to a phone you own: admitted and billed like any call. Optionally tries another dialled-number format for this one call; save the one that was answered with `save_sip_connection_dial_format`. One test call at a time, at most three an hour per number. Refused until the number's ownership is confirmed. |
| `get_sip_connection_test_call` | `numbers:read` | A test call's status: `calling`, `answered` or `failed`, with the SIP status your carrier returned when there is one. |
| `save_sip_connection_dial_format` | `numbers:write` | Save the dialled-number format of an answered test call as the connection's format. |
| `arm_sip_connection_inbound_test` | `numbers:write` | Arm a three-minute window: call the number from any phone, and the call is noted on the number (the caller's last four digits only). The call itself is answered exactly as any other. |

| `get_call_translations` | `recordings:read` | Read the saved machine translations of a call. No paid work is created. |
| `request_call_translation` | `recordings:read` **and** `translations:write` | Request a paid translation of a call's stored text, even with automatic translation off: $0.02 per 1,000 original words needing translation per target language, minimum $0.01. A result that is already ready, and text already in the target language, cost nothing. |

## Campaigns

See [campaigns](/docs/campaigns) for runs, retries, outcomes and the review inbox.

| Tool | Scope | Description |
| --- | --- | --- |
| `create_campaign` | `calls:write` | Create a draft outbound campaign: agent, caller-id numbers, contact list, purpose, consent_basis (existing_customer \| explicit_consent), calling windows, retry policy (or a preset: sales, collections, single_attempt), concurrency and optional schedule. It starts only when launched with launch_campaign. |
| `update_campaign` | `calls:write` | Edit a campaign's settings. A draft accepts every setting; a scheduled or paused campaign accepts name, from_number_ids, calling windows and zone, retry policy, concurrency, ends_at and language (and scheduled_start_at while scheduled). A running campaign accepts no edits until it is paused. Returns the campaign and the list of changed fields. |
| `launch_campaign` | `calls:write` | Authorize and start a draft campaign. Existing-customer / consented lists on active workspace capabilities start immediately; the result carries the authorization decision. |
| `enroll_campaign_contacts` | `calls:write` | Add contacts to a scheduled, running or paused campaign (at most 10,000 per call): they join the campaign's own contact list and its queue in one step and are called inside their calling hours. Idempotent: a contact already in the queue is not added again. Refused when the campaign is a draft, completed or cancelled, or when the audience with these contacts would need review (for example a new destination country). |
| `pause_campaign` | `calls:write` | Pause a running campaign; no new attempts are placed until it is resumed. |
| `resume_campaign` | `calls:write` | Resume a paused campaign. |
| `cancel_campaign` | `calls:write` | Cancel a campaign: queued calls are cancelled, remaining contacts are skipped. |
| `delete_campaign` | `calls:write` | Delete a draft, held, blocked, completed or cancelled campaign: it leaves the campaign listings; its calls, recordings, transcripts and billing records are kept. A launching, scheduled, running or paused campaign must be cancelled first (409 campaign_active); a repeat answers 404. Ask the user to confirm before calling. |
| `duplicate_campaign` | `calls:write` | Copy a campaign's settings into a new draft, optionally with another name, contact list, start and end. The copy keeps the AI agent, caller IDs, calling hours and retries; its concurrency is lowered to today's limit when needed (clamped says so). Nothing is launched. |
| `start_campaign_test_call` | `calls:write` | Place one real phone call, billed like any call, from a draft campaign to one contact of its contact list, with the campaign's AI agent, caller ID and that contact's values. The usual checks apply: do-not-call list, calling rules, balance, the campaign's calling hours, and one unfinished test call per draft. The campaign stays a draft and the contact is called again when it launches. Ask the user to confirm before calling. |
| `list_campaigns` | `calls:read` | List campaigns in the workspace with their latest run and counters (bounded page). |
| `get_campaign` | `calls:read` | Read one campaign with its latest run and contact counters. |
| `list_campaign_contacts` | `calls:read` | List the contacts of a campaign's latest run in list order, a page of at most limit (default 100, at most 500) from offset, with has_more: each one's status, result, attempts so far and next attempt. Each row's id is the contact_id list_campaign_contact_attempts takes. |
| `get_campaign_results` | `calls:read` | List the contacts of a campaign's latest run with what each one's last call came to: the outcome its conversation flow reached, the agent's Result fields and whether a recording and transcript exist. A page of at most limit (default 100, at most 500) from offset, with has_more. |
| `list_campaign_contact_attempts` | `calls:read` | Read one contact's timeline in a campaign: every attempt in order with its kind (first_contact, retry, callback, reopened), result, call id and what the campaign decided next (retry, callback, deferred or finished, and when). Bounded page; contact_id is the id of a campaign contact row. Values the campaign did not record are null. |
| `list_campaign_reviews` | `calls:read` | List a campaign's review inbox: the calls whose conversation flow ended on an outcome marked for review, open ones by default. A page of at most limit (default 50, at most 200) from offset, with has_more. Beside the page, it counts the inbox by outcome and by contact language as stored on each contact; those counts are not paged. Resolve one with resolve_campaign_review. |
| `resolve_campaign_review` | `calls:write` | Mark one review of a campaign as resolved, with an optional note of at most 2,000 characters. With requeue_contact, the contact is put back in the campaign's queue and will be called again (billed), unless its number is on the do-not-call list or the run can no longer call; the answer says when that was refused. A review is resolved once; a second resolve is refused. |

## Simulations Lab

Scripted synthetic callers exercising one of your AI agents. See
[Simulations Lab](/docs/simulations-lab) for what a suite is and what a run
costs.

| Tool | Scope | Description |
| --- | --- | --- |
| `list_simulation_suites` | `agents:read` | An AI agent's suites, each with the health of its latest run. |
| `get_simulation_suite` | `agents:read` | One suite: scenarios, runners, policy, run history, and `run_setup`. |
| `create_simulation_suite` | `agents:write` | Create a suite, optionally with its whole scenario list in one call. |
| `preview_simulation_run` | `agents:read` | What a run would cost and which runners this deployment admits. Creates nothing. |
| `start_simulation_run` | `agents:write` | Start a run. Spends your budget; `idempotency_key` is required. |
| `get_simulation_run` | `agents:read` | One run's status and verdicts. Conversation content and recording references additionally require `recordings:read`. |
| `get_simulation_run_results` | `simulation_suites:read` | The redacted pass/fail projection for a build server. |
| `cancel_simulation_run` | `agents:write` | Cancel a queued or running run. |
| `delete_simulation_suite` | `agents:write` | Permanently delete a simulation suite that has never had a run. Needs its current revision. A suite with run history is archived through the suite API instead. |

The authored configuration and run metadata take `agents:read`.
`get_simulation_run` omits transcript, recording references and facts without
`recordings:read`, along with assertion actual values, rubric rationale and
linked-evidence notes that can repeat conversation content.
`get_simulation_run_results`
takes only `simulation_suites:read`, so a CI job can gate a deploy on a run
without holding a key that reads every AI agent's configuration.

See [Scopes & permissions](/docs/scopes) for the full scope catalog and
fail-closed semantics.
