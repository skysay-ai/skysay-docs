The Skysay API ships a live **OpenAPI 3** document. It is the machine-readable
source of truth for every REST endpoint, request/response schema, and auth
requirement — generated from the running service.

## Open the spec

<Cards>
  <Card title="/control-plane/openapi.json" href="/control-plane/openapi.json" description="The live OpenAPI 3 document, served by the API." />
</Cards>

Point any OpenAPI-aware client at it — Swagger UI, Postman, an SDK generator, or
an agent that reads OpenAPI directly. The same scoped `sky_` Bearer key
authenticates every operation.

## Generated reference and handwritten guides

The [Generated API reference](/docs/api-reference) is a deterministic index of
customer SDK operations built from a checked-in snapshot of that canonical
OpenAPI schema. The snapshot lets the docs build and review offline; it is not a
second hand-maintained API contract. Exact request/response detail remains in
the live OpenAPI document.

Conceptual pages are deliberately handwritten because schemas cannot explain
product ownership or safe use. Read [Integrations](/docs/integrations) for the
signed Action protocol, [Customer applications](/docs/customer-applications) for
the call lifecycle, and [Post-call results](/docs/post-call-results) for signed
events and advisory extraction.
